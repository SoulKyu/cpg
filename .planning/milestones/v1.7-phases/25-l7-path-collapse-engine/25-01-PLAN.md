## Decisions (pinned — research "Next steps" resolutions)

1. **Cross-flush strategy: research option (a), finalize-time collapse over a whole-run path set.** The Aggregator retains a lightweight per-bucket observed-path set (`policy.L7CollapseState.Retained`, keyed opaquely by (direction, peer, port/proto)) instead of nothing; collapse runs at **every flush** over the whole-run set (so the first flush after the gate is crossed already emits the correct authoritative set — no separate finalize-only pass is needed; the final flush/finalize is simply the last authoritative recomputation). **Merge-on-write reconciliation consequence (explicit):** `MergePolicy` union-merges HTTP sub-lists by canonical key, and dedup keys differ between a literal (`^/api/v1/users/7$`) and a template (`^/api/v1/users/[0-9]+$`) — so without reconciliation, literals written before the gate was crossed would persist on disk forever alongside the template, over-permissively. Therefore each collapse-enabled flush marks its `PolicyEvent.ReplaceL7HTTP = true` and the merge layer REPLACES (not union-merges) the HTTP sub-list of each matching (port, proto) bucket. Replacement is safe because each flush's emission is computed over the whole-run path set and is therefore a superset of anything previously written for that bucket; DNS sub-lists (kube-dns companion) are never replaced.
2. **Attribution rollup: keep evidence keyed by literal paths.** `recordL7` attribution is unchanged; `cpg explain --http-path` exact-match keeps working unchanged; evidence files show which literal observed paths back each template. No template-keyed attribution in this phase.
3. **Gate default N = 5** (conservative end of the research-suggested 5–10 range; lower = collapse less often = safer for a security tool; R3's 20 is analytics-oriented prior art, not a security anchor). Flag name stays `--min-flows-per-l7-rule` per REQUIREMENTS.md, but help text and all doc comments say **"distinct observed paths"** (requirement text is authoritative over the flag name). Resolution rule: `policy.ResolveMinFlowsPerL7Rule(n)`: n < 1 → DefaultMinFlowsPerL7Rule (5) — fail-closed, a user cannot disable the gate by passing 0. CLI validation rejects values < 1 with an error; MCP rejects negative `min_flows_per_l7_rule` and treats omitted/0 as "use the default" (zero-value semantics mirroring `defaultDuration`).
